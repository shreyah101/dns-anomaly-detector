## Objective

Identify DNS query patterns that warrant investigation using explainable statistical features. The project demonstrates DNS packet extraction, public-suffix grouping, character distributions, timing analysis, and configuration generation in a common CLI and Streamlit workflow.

## Architecture

CSV logs and decoded port-53 packet captures feed a common validation stage. It normalizes domains, parses timestamps as UTC, validates client IP addresses, derives registered domains, and preserves optional response and query metadata. Packet responses are joined to requests; responses are not counted as additional queries.

The shared pipeline computes lexical features once per distinct domain, temporal features per source IP and registered domain, and contextual features for names and provider suffixes. A weighted score and explicit heuristic adjustments produce a review priority. Each query retains the individual feature measurements used in its explanation.

## Feature definitions

Character entropy is H = -sum(p(c) log2 p(c)). Bigram divergence compares observed pair probabilities with a bundled English reference using natural logarithms and a small smoothing constant. These features characterize strings; neither proves a domain was generated by malware.

Timing uses the sample coefficient of variation of sorted inter-arrival times and T = 1/(1+CV). At least three queries are required. Missing history stays unknown. A regular update agent or monitoring service can produce beacon-like timing.

Label length is transformed by a logistic function using baseline mean 7 and standard deviation 3. A static TLD lookup contributes a project-defined prior. Encoding inspection attempts candidate decoding and estimates decoded byte lengths. A limited dictionary segments candidate compounds. These signals require corroboration and have foreseeable false positives.

## Decision rule

Fixed scaling uses entropy/4.5, KL/18, and bounded values for the remaining signals. Defaults weight these seven signals by 0.25, 0.25, 0.15, 0.15, 0.10, 0.05, and 0.05. Non-negative positive-total custom weights are normalized. Dictionary scores >= 0.70 add 0.35; tunnel scores >= 0.50 add 0.30. CDN and known-name context attenuate weak evidence without bypassing strong encoding or dictionary indicators. Scores are clipped to [0,1].

Queries above 0.60 are flagged for review, above 0.75 receive HIGH priority, and above 0.85 receive CRITICAL priority. These cutoffs are heuristic configuration choices, not statistically calibrated attack probabilities. Mean + z * sample standard deviation is retained as a separate batch-relative outlier marker. The distinction prevents a homogeneous batch from defining away its own suspicious behavior.

## Interface and outputs

The Streamlit workspace has Traffic analysis, Domain inspector, and Method & project pages. Analysis runs on request; results persist across filtering, and setting changes are marked until rerun. Users can inspect a domain/client pair, download scored CSV and evidence reports, review timing and observed NXDOMAIN rates, and select flagged domains for export previews.

Exports include Suricata signatures, RPZ, hosts blocklists, an illustrative plaintext UDP iptables filter, a Windows hosts script, and STIX indicators with UUID identifiers and UTC timestamps. These outputs are configuration drafts, not proof of malicious activity. No rules are applied automatically.

## Validation and reproducibility

Run `python -m pytest -q` for component and regression checks, and `python main.py --report --top 10` for current sample results. Regression tests cover score consistency, malformed input, preserved response codes, insufficient history, tied-score AUC, incomplete labels, domain validation, export identifiers and packet request/response attribution. Test pass counts describe tests executed, not code coverage.

The bundled dataset and generated PCAP are synthetic. Precision, recall, F1 and AUC must be reported with the dataset and current configuration. Claims of 100% real-world precision, comparisons with Random Forest/LSTM, and sub-millisecond performance in earlier report drafts are unsupported and are not adopted here.

## Limitations and future work

A broader independently labeled capture collection is needed for threshold selection and false-positive measurement. English-domain features can penalize non-English naming. CDN providers host untrusted tenants. TCP stream reassembly, encrypted DNS, packet-loss recovery, and unique payload reconstruction remain future work. The standalone spectral helper is experimental and does not affect the current detector. Live capture requires a supported capture driver and privileges and must not be confused with synthetic demonstration data.

## Conclusion

The implementation provides a reproducible DNS traffic review tool with accessible per-query evidence. It demonstrates networking and statistical methods while keeping heuristic findings distinct from confirmed incidents.
